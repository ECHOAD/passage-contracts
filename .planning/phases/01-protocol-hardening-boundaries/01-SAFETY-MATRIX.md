# Phase 1 Safety And Cutover Matrix

| Contract Family | Pause | Migrate | Admin/Operator Model | Cutover Notes | Test Gate |
|---|---|---|---|---|---|
| registry | Yes | No explicit migrate entry today | Admin + operators for most protocol admin paths, plus recovery council for ownership-recovery actions | No in-place migrate entry means schema or authority changes require coordinated replacement or manual state migration. Authorized-minter pagination now scopes correctly inside collection prefixes. | `cargo test -p registry --lib --tests` |
| collection-factory | Yes | No explicit migrate entry today | Admin + operators, with registry-mediated creator and ecosystem approval checks | Reply handling now depends on instantiate reply data. Cutover must preserve pending creation records because there is no migrate entry to repair in-flight factory state later. | `cargo test -p collection-factory --lib` |
| ecosystem-factory | Yes | No explicit migrate entry today | Admin + operators, with registry cross-admin checks on creation flows | Reply handling now depends on instantiate reply data. Any upgrade or replacement must drain pending ecosystem creations before cutover. | `cargo test -p ecosystem-factory --lib` |
| split-router | Yes | No explicit migrate entry today | Admin only | The contract is a narrow settlement primitive. Any state-shape change requires redeploy plus recipient configuration replay because there is no migrate entry. | `cargo test -p split-router --lib --tests` |
| streaming-billing | Yes | No explicit migrate entry today | Admin for config and emergency actions, backend operator for session lifecycle, fiat oracle for card purchases, verified world owner or admin for world-rate setup | This family is service-invoked. Session lifecycle, fiat reporting, and cutover orchestration must stay coordinated with Passage services. Without a migrate entry, upgrades need replacement or manual state migration. | `cargo test -p streaming-billing --lib` and `cargo check -p streaming-billing` |
| marketplace-v3 | Yes | Yes | Admin + operators, with registry allowed to register collections when configured | Brownfield query surfaces now honor declared filters and cursors. Future cutovers must preserve multi-collection indexes and provide the required migrate inputs from older marketplace state. | `cargo test -p marketplace-v3 --lib` |
| minter-v2 | Yes | Yes | Admin only for privileged mint and config paths, with optional registry authorization for mintability | Migration paths already exist, but cutover must keep registry wiring and optional base-token-uri behavior aligned to the selected source state. | `cargo test -p minter-v2 --lib --tests` |
| minter-v2-metadata-onchain | Yes | Yes | Admin only for privileged mint and metadata configuration paths, with optional registry authorization | Migration paths already exist, but cutover must preserve native asset templates, metadata overrides, and registry configuration across legacy state shapes. | `cargo check -p minter-v2-metadata-onchain` |
