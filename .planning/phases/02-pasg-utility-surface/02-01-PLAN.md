## Must Haves

### Truths

- `upasg` is the canonical PASG settlement denom in this repository.
- The canonical PASG utility interface must live in one source-of-truth message/query surface, not in per-consumer fee logic.
- No contract in this phase may absorb platform billing, subscription, or other off-chain business rules.
- If a wrapper exists, it is a compatibility shim only and must preserve native `upasg` semantics.

### Artifacts

- `contracts/core/streaming-billing/src/msg.rs` defines the canonical PASG utility messages and queries.
- `contracts/core/streaming-billing/src/contract.rs` wires the utility surface into validation, enforcement, and query plumbing.
- `contracts/core/streaming-billing/src/state.rs` persists the PASG utility stance and any compatibility metadata.
- `contracts/core/streaming-billing/src/tests.rs` holds package-local regression coverage for denom and interface invariants.
- `contracts/core/streaming-billing/README.md` states the contract-level PASG utility behavior.
- `README.md` and `CLAUDE.md` state the repo-wide native-denom position for integrators.

### Key Links

- From `contracts/core/streaming-billing/src/msg.rs` to `contracts/core/streaming-billing/src/contract.rs` via config, query, and execute entrypoints.
- From `contracts/core/streaming-billing/src/msg.rs` to `contracts/core/split-router/src/msg.rs` only through generic routing compatibility, not PASG policy duplication.
- From `contracts/core/streaming-billing/README.md` to `README.md` via the native-denom-first repo narrative.
