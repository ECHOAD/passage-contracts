# Phase 03-01 - Separate Governance Layer And Admin Bridge

## Objective

Introduce PASG governance as a new contract family instead of rewriting `contracts/core/multisig`, and define the bounded execution bridge that lets passed PASG proposals reach the existing admin-owner plane without erasing signer-based admin control.

This wave is architectural foundation, not the full voting-power implementation. By the end of the wave, the repo must have one explicit story:

- `multisig` remains the stable owner/admin contract for `registry` and other protocol contracts
- PASG governance lives in a separate `contracts/core/pasg-governance` package
- governance execution reaches owned protocol contracts through a bounded bridge into the admin multisig

## Must Haves

### Truths

- `contracts/core/multisig` stays signer-threshold based and remains the owner/admin surface for `registry` and similar protocol contracts.
- PASG governance is implemented in a separate `contracts/core/pasg-governance` contract, not by repurposing `multisig`.
- The governance layer may trigger protocol actions only through an explicit bridge in the admin plane; it must not silently bypass or replace the owner/admin model.
- Governance scope remains limited to PASG and protocol parameters, not platform billing, subscriptions, search, moderation, analytics, or other off-chain operations.

### Artifacts

- `contracts/core/pasg-governance/src/msg.rs` defines the new governance instantiate, execute, and query surface.
- `contracts/core/pasg-governance/src/state.rs` stores governance config, proposal records, and execution-bridge metadata.
- `contracts/core/pasg-governance/src/contract.rs` creates proposal lifecycle and the bounded `ExecutePassedProposal` flow that targets the multisig bridge.
- `contracts/core/multisig/src/msg.rs` and `contracts/core/multisig/src/contract.rs` expose a dedicated governance-controlled execute entrypoint without changing signer voting semantics.
- `contracts/core/multisig/README.md` and `docs/04-multisig-governance.md` document the admin-owner role and the new governance relationship.

### Key Links

- From `contracts/core/pasg-governance/src/contract.rs` to `contracts/core/multisig/src/msg.rs` via a dedicated governance bridge message rather than `Propose/Vote/Execute` signer flow.
- From `contracts/core/pasg-governance/src/msg.rs` to `contracts/core/pasg-governance/src/state.rs` via proposal action definitions, allowed target configuration, and admin bridge configuration.
- From `docs/04-multisig-governance.md` to `contracts/core/multisig/README.md` via the shared explanation that `multisig` remains the owner/admin shell.
