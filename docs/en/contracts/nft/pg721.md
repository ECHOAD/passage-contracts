# pg721

## Status

Current

## Purpose

Defines the main typed Passage collection contract used for creator assets and durable on-chain asset semantics.

## Instantiation

Instantiate with collection ownership/admin data, NFT-type metadata, royalty behavior, and the collection-scoped rules enforced by the base collection model.

Real payload source of truth: `contracts/nft/pg721/src/msg.rs` and `schema/` when available.

## Actors and permissions

Collection owner/admin, minters, marketplaces, registry, and token holders.

## Key messages

- Stores collection-scoped typed metadata and ownership rules.
- Supports minting, transfer, approval, and royalty-aware collection behavior.
- Acts as the core collection surface that minters and marketplaces build around.
- Keeps `token_uri` as the manifest pointer for rendering, runtime detail, and expanded compatibility metadata.
- Keeps `profile_id` as a minimal Passage compatibility marker where avatar or companion interoperability matters.
- Does not treat mutable gameplay or install-state facts as generic NFT metadata.

## Relationships

- Is commonly deployed through `collection-factory` or `minter-v2`.
- Feeds collection identity and NFT type into registry.
- Sits underneath marketplace, auction, whitelist, and royalty-group flows.
- Pairs with dedicated state surfaces such as `asset-progression` and `world-plugin-assignment` when mutable protocol state must be persisted.

## Hypothetical example

Hypothetical flow: an avatar collection uses `pg721` for ownership, approvals, and typed identity while the manifest behind `token_uri` carries render payloads and any world-specific runtime descriptors.
